## 3. Load-time diagnostic

R014's hook failed because MTLCompiler is loaded lazily and the
`DYLD_INSERT_LIBRARIES` diagnostic did not install in time. R024 changed
the mechanism:

1. The owned compiler copy (`MTLCompilerService.real`, originally
   SHA-256 `4d318283…ea6f`, CDHash `d0410d89…`) was patched by inserting
   one `LC_LOAD_DYLIB` in its header padding (end of load commands
   `0x910`, first section `0x20c4`). The added dependency is
   `/var/jb/usr/macOS/Frameworks/Metal.framework/XPCServices/MacWS/r014/service/r024_diag.dylib`.
   Patched SHA-256 `7bc22e08e234c18fb5a230f930edf5ea0665fe32bf46eae8a3ba9ab9538bce32`;
   re-signed CDHash `b3e29eef5732b354712a1e1fc1ec28b99fa55e31`.
2. The service executable is **arm64e**. A first arm64 diagnostic dylib
   was rejected by dyld (`incompatible architecture (have 'arm64', need
   'arm64e')`); the load-command path therefore requires an arm64e dylib.
   The final `r024_diag.dylib` is arm64e, SHA-256
   `61aec4daf617266d524823a2ad12f2ba31ed30d9b291e984018969ac9bc20a8c`,
   CDHash `d0b584a81182108449251b878ff940efd5243516`, trustcached.
3. The diagnostic constructor runs before the service main, `dlopen`s
   `/System/Library/PrivateFrameworks/MTLCompiler.framework/MTLCompiler`,
   and hooks the fatal handler immediately.
4. The wrapper (`r024_wrapper`, CDHash `44767b6a…`) redirects stderr and
   execs the patched copy; the bundle plist `CFBundleExecutable` is
   `r024_wrapper`.

### Hook entry correction

The crash frame previously used as an offset (`0x798bc`) is a **return
address** inside `fatalDiagnosticHandler`, not its entry. The crash
report gives `symbolLocation=96` (0x60), so the entry is
`0x798bc - 0x60 = 0x7985c`. R014's hook at 0x798bc therefore never
intercepted the call.

Verified hook evidence from the private service:

```
R024-DIAG-BASE base=0x1fc256000 handler=0x1fc2cf85c
R024-DIAG-ENTRY before=d503237f d10103ff a9024ff4 a9037bfd
R024-DIAG-ENTRY after=58000050 d61f0200 ...
R024-DIAG-HOOK-INSTALLED original=0x... changed=1
```

The prologue bytes change after `MSHookFunction`; the handler fires on
the type-15 request.
