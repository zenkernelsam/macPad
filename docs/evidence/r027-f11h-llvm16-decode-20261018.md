## R028 correction — provenance and text-equality explanation

The disputed original artifacts are slices of **one** 6,944-byte MTLB
record: the 6,924/`454ad619…` value is payload plus 8 zero padding, the
6,916/`ce018722…` value is the wrapper-declared payload, the wrapper is
6,936/`e3876cba…`. There is no conflicting original.

The normalized textual equality in this R027 record is explained by the
LLVM16 intrinsic-attribute auto-upgrade: `Function::Function` and
`UpgradeIntrinsicFunction` apply canonical intrinsic attributes in
memory, so llvm-dis prints the upgraded lifetime group for both modules
even though the original wire lacks those attributes. It does **not**
prove original wire preservation. The original wire group is
`[argmemonly,nounwind]`; the converted/request group adds
`nocallback(71), nofree(62), nosync(63), willreturn(61)`. R028's direct
A/B with the original-retargeted module has no ID71 and returns the
downstream `Target OS is incompatible.` reply. See
`r028-f11h-compatibility-candidate-20261018.md`.
