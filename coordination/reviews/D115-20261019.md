# D115 review — atomic admission repair and remaining teardown boundary

Reviewed 2026-10-19 18:47 Asia/Hong_Kong after exact-role session/PID/TTY/
cwd checks. Frontend ACP3775/ttys000 and backend ACP3901/ttys001 both had
explicit handover. No production/device operation.

## D115 outcome accepted with limits

Backend replaced the separate shutdown + in-flight counters with one
`adm` word (CLOSED bit plus active-op count), and adds the external owner
rule for joining/preventing callers before free. This is the right narrow
repair for the reproduced interleaving: an admitted operation cannot be
omitted from quiescence; a pre-admit caller resumes to a closed admission
while the object is still alive under the owner rule. The backend reports
ASan lifecycle L1–L6, D114 C0–C12 and D112 16/16 prototype controls passing.
Reported L4 was corrected to count `drain_final`'s own residue drops.

Frontend independently confirmed the D114 race and the limits of any
in-object admission word. It identified the next lifecycle gaps below.

## Remaining issues — production candidate stays PENDING

Source review of D115 `d113_transport.c`:

- `d113_drain()` reads `t->fd` before `d113_drain_fd()` calls `admit()`;
  concurrent close/reopen can invalidate or redirect that fd before write.
- `d113_drain_close()` and `d113_drain_open()` mutate the fd without
  coordinating with admitted drains. An fd close/reuse can direct trace
  bytes to an unrelated file. The drain call itself has to acquire
  admission before reading the fd, and open/close need an explicit owner /
  exclusive lifecycle boundary.
- `d113_drain_final()` checks quiescence and calls `drain_loop()` directly
  without claiming an exclusive final-drain phase. Concurrent final drains
  can race; concurrent `free()` can release the object while final drain is
  using it. `d113_free()` is still check-then-free, so two owners can both
  observe quiescence and double-free.
- A raw pointer caller paused before its first object access, or a caller
  starting after free, cannot be protected by in-object atomics. The stated
  external owner contract is mandatory and must explicitly cover each API
  entry and teardown serialization.

These are offline source-level findings, not observed production failures.
They are supported by the exact code paths and are recorded as design
hazards until bounded tests or an explicit API ownership contract close
them.

## Disposition

Accept D115's producer admission improvement as isolated prototype evidence.
Do not approve production integration. Dispatch D116 to resolve the drain,
fd, final-drain and single-shot teardown boundaries with deterministic
tests and a precise external lifetime contract. No device/build/deploy/
restart/trustcache/Git action.
