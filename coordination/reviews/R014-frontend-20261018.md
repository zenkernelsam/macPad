tool as substitutes for cache-global GOT/fixup evidence. It identifies the
arm64/arm64e LLDB mismatch, avoids using dyld 1286.10 as Ventura 1066.8 fact,

## Required clarification before device use

The plan currently proposes distinguishing 32-byte versus 48-byte mapping
records by checking whether parsed addresses and file bounds look plausible.
Plausibility is not an exact format witness. Since 22F82 dyld is 1066.8 and
only 1286.10 headers are local, the plan must state a positive, version-matched
validation source for the header fields, mapping discriminator, subcache
array, and patch-info schema. If no such source/tool exists, the procedure
must stop after collecting identity and bounded raw header bytes; it must not
read a derived target page or interpret patch-info fields.

R015 is limited to this clarification and evidence-note correction. Backend
R010 remains the only device owner and is still building; no cache capture is
authorized through the frontend packet.
