## Correction from D148 independent review

The original review draft incorrectly claimed that T12 resets `hook_gate` but
not `hook_entered`. D148 verified `d141_svctime_test.c:278` resets both, and
`d141_reset_for_test` clears the hook pointer; the stale-flag defect does not
exist. T12 still fails D145 B1 because it never attempts the exact parked
producer's `c+CAP` claim while that producer remains uncommitted. D148 also
found a real gate-init race: a `gate_init` caller that loses its CAS to
`set_generation` sees INITIALIZING then UNINIT, but its bounded loop only
accepts ARMED/DISARMED and never retries the CAS. It can return -1 even though
this was the first gate call; T13 requires gate_rc==1, so the deterministic
barrier should force and test this interleaving.
