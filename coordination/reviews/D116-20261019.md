## Reproduced fd alias race

`d113_drain_close()` / `d113_drain_open()` load `adm` and check that no
drainer/phase bit is present, then mutate `fd`. This is not an exclusive
claim. A drainer can be admitted after the check and capture the old fd
before close/reopen runs.

I inserted a deterministic test hook only in a temporary copy of
`d113_transport.c`, after the mutator's zero-drainer check and before
`close(t->fd)`. The test paused close there, admitted a drainer and paused
it before `write`, resumed close, opened a replacement file to reuse the
fd number, then resumed the drain. Repository source was unchanged.

```text
clang -fsanitize=address -g -Ianalysis/d113-trace-transport \
  -o /tmp/macpad_d116_close_race_test \
  /tmp/macpad_d116_close_race_test.c /tmp/macpad_d116_close_race.c -lpthread
ASAN_OPTIONS=detect_leaks=0 /tmp/macpad_d116_close_race_test
```

Verbatim result:

```text
close_rc=0 drain_rc=1 fileA=0B fileD=71B
```

This proves the D116 guard can still close/rebind an fd while a drainer
uses it. The same gap exists in `d113_drain_open`. Required fix: atomically
claim an fd-mutation phase in `adm` before checking counts and hold it
through close/open and publication of the new fd. Drainer admission must
refuse while that phase is held. Keep all syscalls outside lock-held
producer paths.

## Quiescence phase reporting defect

In a temporary focused ASan test, I paused `d113_drain_final()` at its
existing hook after it claimed `FINAL`, then called `d113_quiesced()`:

```text
FINAL held, d113_quiesced=1 (expected 0 while final drain is active)
```

`d113_quiesced()` checks CLOSED and count bits but ignores FINAL/FREEING.
`tready()` does check phases, so current `free` refuses FINAL, but the
public quiesced predicate is inconsistent with its documented meaning.
Include phase bits in its false condition and add a focused test.
