# D206 backend — analysis-only typed PASS wrapper contract harness

Implement a tiny offline candidate under analysis/d206-pass-wrapper-candidate, leaving production and accepted candidates unchanged. D205 identified that d141_wrap_pass's uintptr_t(void*) callback cannot represent the proposed int(int,double) services-pass ABI. Build a typed wrapper that accepts an explicit original function pointer int (*)(int,double), emits D141 PASS_ENTER, calls original exactly once, emits PASS_EXIT and returns original int result unchanged. Use accepted d141_emit only; no MSHookFunction, permits, binary offsets, runtime symbol calls, WS/SkyLight or sender invocation.

Host tests with stub originals must prove int arg and double object bits (including -0.0 and finite values) arrive unchanged, return int and errno preserved, call exactly once, PASS_ENTER/EXIT same measured tid and correct order, sentinel-disarmed path calls original but emits nothing, and no cast through a wrong function type. Ring metadata uses the accepted set_generation/accessor. Test collection after originals return using bounded existing drain; do not hold locks around the original. No product build wiring, sentinel choice change or diagnostic integration. Fatal/non-returning original produces no EXIT by definition; document rather than bypass it. Run ASan/UBSan and arm64 object compile (TSan only if meaningful concurrent tests included); report exact results. No commit before review.
